# 第 1 章 产品概述


## 1.1 产品背景

《智能待办事项系统 V1.0》（PRD-TDL-2026-001）交付了浏览器端基础待办事项网页，覆盖任务增删改查和本地持久化。随着 πOS 管线体系在组织内落地，产品面临两项新挑战：一是待办工具与工作流管线相互割裂，用户须在多个系统间手动同步状态；二是移动场景下手动输入任务摩擦较高。V2.0 引入语音录入、语音触发管线和管线状态同步能力。V3.0 在 V2.0 功能基础上完成架构升级，采用 B/S 全栈架构（React+Vite 前端 + Node.js/Express 后端 + SQLite 数据库），将数据持久化从浏览器本地迁移至服务端，实现跨设备访问，并通过后端代理解决 πOS API 调用的 CORS 问题，将待办事项升级为可多端共享的智能任务中心。

## 1.2 一句话定位

## 3.5 典型场景

场景 1：桌面端快速录入并筛选今日任务 用户打开工具，通过"进行中"筛选聚焦待处理任务，完成后切换"已完成"核对——需保持网络连接以访问后端，无需额外登录。
场景 2：移动端语音快速录入碎片想法 通勤中长按录音按钮，松开后识别结果自动填入输入框，确认后一键提交，全程不超过 5 秒。
场景 3：语音触发管线 语音录入完成后，弹出已配置管线列表，选择目标管线并二次确认触发，系统记录触发频率。
场景 4：管线执行失败后处置 管线返回 failed，任务旁显示红色警告标签，用户了解失败原因后选择重新触发或手动标记完成。
场景 5：高频管线推荐 某管线 7 天内触发 3 次，推荐卡自动出现在侧边栏，用户点击"立即触发"快速复用，无需手动查找管线 ID。
场景 6：语音识别失败降级 环境噪音导致识别失败，输入框保持空白，提示重试或手动输入，流程不中断。

# 第 8 章 AI 与语音信任设计


## 8.1 信任设计目标

本系统引入 Web Speech API 语音识别及 πOS 管线自动触发，带来便利的同时引入两类新风险：语音误识别导致的错误内容录入，以及语音误触发导致的非预期管线执行。从透明度、可纠错、可撤销三个维度规定信任设计要求。

## 8.2 三支柱信任框架


### 支柱一：透明度——用户知道系统正在做什么

识别状态可见：识别中持续脉冲动效+"正在识别..."文字标签，双信号确保色觉障碍用户可感知
权限透明：首次请求麦克风权限时展示说明文案，拒绝后按钮禁用并常驻提示
识别来源标注：语音填入的文本在输入框右侧显示"语音识别"角标，用户手动修改后消失
管线触发透明：触发中显示进度状态，自动完成后显示"由管线自动完成"角标区别于手动完成

### 支柱二：可纠错——用户能修正系统输出

识别结果可编辑：识别结果填入输入框后不自动提交，用户可任意修改
预期管理：功能首次使用时展示引导提示："语音识别可能存在偏差，请在提交前确认文本内容"
触发前可核验：二次确认对话框同时展示管线名称和识别文本，用户可核验两项关键信息

### 支柱三：可撤销——用户能撤回非预期操作

管线触发必须二次确认：确认对话框默认焦点在"取消"按钮，防止误按回车触发
触发后撤回窗口：触发成功后 5 秒内显示撤回提示栏（若 πOS API 不支持取消，则提示用户前往管线控制台）
自动完成可恢复：管线自动完成后用户可取消勾选恢复进行中，不受后续轮询干扰（BR-14b）

## 9.3 推荐触发规则

三条件同时满足时触发推荐：
条件 A（频率门槛）：过去 7 天内 pipeline_stats 中该管线的 trigger_count ≥ 3（SQL：COUNT(*) FROM pipeline_events WHERE pipeline_id=? AND triggered_at > datetime('now','-7 days')）
条件 B（冷却期）：pipeline_stats.last_recommended_at 为 NULL 或距当前超过 24 小时
条件 C（抑制期）：pipeline_stats.suppress_until 为 NULL 或当前时间已超过 suppress_until
同一时刻最多展示 1 张推荐卡，多管线满足时按 7 天触发次数降序选取。

## 10.3 安全与数据保护

XSS 防护：所有用户输入内容渲染至 DOM 时，必须使用 textContent 或 createTextNode，严禁使用 innerHTML 插入用户输入；管线名称若来自 API 响应，渲染前同样须转义。
API Token 安全：πOS API Token 配置于后端 .env 环境变量，不通过前端界面传输，不出现在任何 HTTP 响应体或浏览器可见存储中；前端仅与本系统后端通信，不直接持有 Token。
服务端数据安全：任务、管线配置等数据存储于服务端 SQLite 文件，访问须经后端服务；运维方负责数据库文件访问权限和定期备份；不建议将后端直接暴露于公网而不加认证层。

## 10.4 合规与免责说明

语音识别准确率免责：Web Speech API 由浏览器厂商引擎提供，系统不承诺识别准确率；误识别后系统提供编辑与删除功能，最终操作结果由用户确认负责。
管线触发免责：触发前须经用户明确确认；确认后触发的管线操作，最终决策责任归属用户。
浏览器兼容性声明：支持范围 Chrome ≥ 90、Edge ≥ 90、Safari ≥ 14；Internet Explorer 不在支持范围内。
数据持久化免责：因服务器磁盘故障、运维误删除 SQLite 文件或未及时备份导致的数据丢失，属运维范畴，不属于本系统软件交付缺陷；建议运维方每日备份数据库文件至对象存储。

[TABLE]
术语 | 含义
任务 / Task | 用户创建的一条待办记录，含名称、状态（进行中/已完成）、可选关联管线 ID
管线 / Pipeline | πOS 平台的自动化工作流，有唯一 Pipeline ID，可通过 REST API 触发和查询状态
Web Speech API | W3C 语音识别标准接口，Chrome/Edge/Safari 原生支持，Firefox 桌面不支持
状态联动 | 管线执行状态变更时，自动同步到任务状态的机制
频率推荐 | 基于管线触发次数统计、达到阈值后向用户展示推荐卡的功能
SQLite | 服务端嵌入式关系型数据库，文件形式存储，支持 ACID 事务；本系统后端采用 better-sqlite3 驱动
Bearer Token | HTTP 认证令牌，格式 Authorization: Bearer ，用于 πOS API 调用
CORS | 跨源资源共享，浏览器安全策略；本系统前端仅访问本系统后端（CORS 由后端 cors 中间件配置），不直接调用 πOS API
DoD | Definition of Done，完成定义，用于验收判定的可验证清单
PRD | Product Requirements Document，产品需求文档（本文件）
SRS | Software Requirements Specification，需求规格说明书（SRS-TDL-2026-002）
北极星指标 | 产品阶段内最能反映核心价值的单一关键度量，用于牵引决策方向
React + Vite | 前端框架组合：React 18 组件化 UI + Vite 5 构建工具（极速 HMR 和生产打包）
Express | Node.js 轻量级 Web 框架；本系统后端 REST API 服务及 πOS API 代理均由 Express 实现
B/S 架构 | 浏览器/服务器架构：前端运行于浏览器，后端运行于服务器，数据存于服务端
REST API（后端） | 本系统 Node.js/Express 提供的 HTTP 接口，前端通过此接口读写任务和触发管线
[/TABLE]
