# 第 1 章 引言


## 1.1 编写目的

本文件面向开发团队、测试团队、项目经理及客户代表，完整定义智能待办事项系统的功能边界、数据规格、非功能指标及验收口径，作为开发实施和验收测试的技术基准。
本版本（V3.0）在 V2.0 基础上，完成架构升级：由单文件纯前端重构为 B/S 全栈架构（React+Vite + Node.js/Express + SQLite）。V2.0 已纳入的三项智能能力扩展（移动端语音转文字、管线执行状态联动、智能管线推荐）延续执行，交付策略维持分两期。

## 1.2 项目背景

用户在日常工作中需要一个轻量级任务管理工具，用于记录和追踪日常待办事项，同时希望与已有的 πOS/DevHub 工作流管线无缝联动——语音说出任务即可自动创建并触发对应管线，管线执行完成后任务自动标记完成，高频使用的管线模式能被系统自动识别并推荐。
现有待办工具与工作流管线割裂，用户需要在多个系统间手动同步状态，操作摩擦高。本项目采用 B/S 全栈架构（React+Vite 前端 + Node.js/Express 后端 + SQLite 数据库），将任务管理与 πOS 工作流管线打通，实现跨设备数据持久化与工作流智能联动。

## 1.3 范围


### 1.3.1 第一期范围内（IN SCOPE — 基础功能 + 语音）

任务添加：输入框提交，空文本不允许
任务删除：点击删除按钮，删除前弹出确认提示
完成标记：复选框切换进行中/已完成状态
任务编辑：双击任务名称触发内联编辑，回车/失焦保存，空文本恢复原值
状态筛选：全部 / 进行中 / 已完成 三档过滤，切换不丢失数据
数据持久化：任务数据通过后端 REST API 写入 SQLite 数据库，刷新或关闭重开后完整保留；支持同一后端多设备访问
移动端响应式布局：断点 768px，适配手机浏览器
语音录入：录音按钮（长按录音、松开识别），调用 Web Speech API，识别结果以文本填入输入框供用户确认后提交
语音触发管线：识别完成后可从已配置管线列表中选择一条触发，触发前弹窗二次确认
交付物：React+Vite 前端工程 + Node.js/Express 后端工程（含 SQLite 数据库初始化脚本及部署说明文档）

### 1.3.2 第二期范围内（IN SCOPE — 管线集成 + 智能推荐）

管线配置页：填写 πOS API baseURL，添加/删除管线（Pipeline ID + 显示名称）；Bearer Token 由运维人员配置于后端 .env，不通过前端页面录入
任务关联管线：每条任务可关联一条已配置管线 Pipeline ID
状态轮询同步：每 30 秒轮询关联管线执行状态，映射为任务状态变更（详见 FR-13/FR-14）
手动关闭同步：全局开关允许用户停止轮询
管线触发频率记录：记录每条管线的触发次数和最近触发时间
推荐卡展示：满足推荐触发条件（7 天内 ≥3 次）时在侧边栏显示推荐卡
推荐反馈：用户可标记推荐是否有用

### 1.3.3 两期均在范围外（OUT OF SCOPE）

用户账号体系（注册/登录/权限管理）
Firefox 桌面端语音识别（Web Speech API 不支持，用户书面接受此限制）
IE 11 及其他已淘汰浏览器兼容
优先级标记、截止日期、分类标签、任务提醒等扩展字段（第一、二期不实现）
数据导出/备份、拖拽排序、批量操作、任务归档
AI 大模型辅助分析（推荐功能采用规则统计，不接入 LLM API）
πOS 管线的创建、编辑、管理（仅集成触发和状态读取）
多用户账号隔离、企业级权限管理（单用户后端，不实现多租户）

# 第 12 章 责任边界与免责

语音识别准确率：Web Speech API 属浏览器原生能力，识别质量由浏览器厂商控制。本系统不对识别准确率作出承诺，误识别导致的任务错误或管线误触发，经用户确认操作后，最终决策责任归属用户，系统提供撤销/编辑功能作为补救。
管线执行结果：本系统仅负责按用户指令调用 πOS API 并展示返回状态，管线本身的执行逻辑、执行成败由 πOS 平台负责，与本系统无关。
数据存储可靠性：系统采用 SQLite 数据库持久化存储，提供 ACID 事务保障。因服务器磁盘故障、运维误操作或未经授权的文件删除导致的数据丢失，属运维范畴，不属于本系统软件交付缺陷。建议运维方启用定时备份（如每日备份数据库文件至对象存储）。
πOS API 访问中断：因 πOS 平台不可用、Token 失效等原因导致后端代理请求失败时，后端返回结构化错误响应，前端展示友好提示，不崩溃。管线触发失败或状态同步中断不属于本系统交付缺陷。

React | 前端 JavaScript UI 框架，采用组件化开发模式；配合 Vite 构建工具实现极速开发和生产打包

Express | Node.js 轻量级 Web 框架，本系统后端采用 Express 提供 REST API 服务和 πOS API 代理
B/S 架构 | 浏览器/服务器架构：前端运行于浏览器，后端运行于服务器，通过 HTTP REST API 通信；数据存于服务端
REST API（后端） | 本系统 Node.js/Express 提供的 HTTP 接口，前端通过此接口读写任务数据和触发管线
